# obsws: obs-websocket v5 protocol as shipped in OBS 31.1.2 (obs-websocket 5.6.2), the obs-websocket-js client, recording-time sync, and hybrid MP4 chapters

## SUMMARY
OBS 31.1.2 ships obs-websocket 5.6.2 (submodule 40d26db, rpcVersion 1), not the 5.7.x at HEAD, so the spec must target 5.6.2 (146 requests, 57 events) and skip the 5.7 canvas APIs. The handshake is Hello(op 0) -> Identify(op 1) -> Identified(op 2). Auth is base64(sha256(base64(sha256(password+salt))+challenge)), confirmed in Crypto.cpp. Note that the auth example in the docs is not a valid test vector. The server runs every incoming message on a QThreadPool. Separate requests and events can therefore run or arrive out of order, and only a RequestBatch guarantees order. StartRecord, StopRecord and the pause requests only queue a call on the Qt UI thread, so success means "queued". The client must wait for RecordStateChanged STARTED or STOPPED, and those events carry no timestamps. CreateRecordChapter (added in 5.5.0) works only when the live file output is mp4_output, i.e. RecFormat2=hybrid_mp4, and the recording is not paused. Otherwise it returns 702 with "Verify that the output being used supports chapter markers."; when not recording it returns 501. The output type is chosen only when OBS builds its outputs (startup, Settings Apply or a profile switch). So SetProfileParameter(RecFormat2) by itself does not turn chapters on, and a dedicated profile is the right fix. This Mac currently uses Simple mode with fragmented_mov at 1280x720, and the websocket server is disabled (server_enabled=false), so chapters would fail today. The chapter timestamp is the DTS of the last muxed video packet (ms resolution), which runs behind real time by the encoder pipeline. OBS stores chapters as an Apple QuickTime chapter text track (tref/chap, no Nero chpl) written only at finalization. FFmpeg reads that track with -show_chapters and carries chapters through a remux (shifted by -ss), and its MP4 muxer writes both QT and Nero chapters. One race matters: STOPPED is signalled before OBS's buffered writer (up to 256 MiB) flushes and closes the file. The tool must therefore wait for a stable, readable file. For the ±100 ms target, STARTED arrival time and GetRecordStatus.outputDuration (frame-quantized and behind the encoder) are too coarse alone. The most precise OBS-side marker is a SerialFrame batch that flashes a color source during a pre-roll trimmed later; these batches run in the graphics tick, so the flash lands on an exact frame. An audio clap on track 2 is possible but its jitter is unmeasured. The iPhone-to-OBS capture latency must be measured separately. obs-websocket-js 5.0.8 (MIT, maintained, types for 5.7.2) works on Node 22, but its Node ESM default import is msgpack, it has no timeouts, and pending calls hang forever on disconnect. A zero-dependency client on Node 22's stable global WebSocket is about 150–250 lines. PATH ffmpeg on this Mac is 4.4.7 (ffmpeg@4 is the linked version); 8.1.1 is installed but unlinked.

## RISKS
- [high] CreateRecordChapter returns 702 because the active file output is not mp4_output (current profile uses fragmented_mov; changing RecFormat2 at runtime does not recreate the output).
  why: OBS chooses mp4_output vs ffmpeg_muxer only when it builds its outputs (startup, Settings Apply, profile activation). This Mac's profile 'Untitled' is fragmented_mov.
  spike: With OBS open, create a dedicated profile 'Contrarregra' (CreateProfile, wait for CurrentProfileChanged; or prepare it once by hand) and confirm GetProfileParameter(SimpleOutput,RecFormat2)='hybrid_mp4'. StartRecord, wait for STARTED, then CreateRecordChapter ×3 with UTF-8 titles (e.g. 'Cena 9 — Modo avião'), StopRecord, wait for finalization. Run ffprobe 8.1.1 and 4.4.7 with -show_chapters -of json.
  success: 3/3 CreateRecordChapter return code 100; ffprobe lists the 3 titles byte-exact (plus at most one auto 'Start'/'Iniciar' at 0); the last chapter ends at the file duration ±1 frame; same result in both ffprobe versions.
  planB: Do not rely on OBS chapters. Write chapters in post from the Mac scene log via ;FFMETADATA1 + ffmpeg -map_chapters 1 (MP4 output gets QT chapter track + Nero chpl), and keep CreateRecordChapter as best-effort live markers.
- [high] Tool reads the MP4 before OBS has flushed moov and chapters (STOPPED arrives before buffered_file_serializer_free).
  why: mp4_output_actual_stop signals stop (STOPPED event) before draining a write buffer of up to 256 MiB and calling fclose; ffprobe then sees a fragmented file with no chapters or fails.
  spike: For 10 takes of 1, 5 and 10 min at 1170x2532@60, log hrtime of STOPPED receipt, the first time ffprobe -show_chapters returns the expected count, the time the file size has been stable for 500 ms, and the OBS log line 'MP4 file output complete. Finalization took N ms'.
  success: Finalization detector never yields a partial file (0 false positives in 30 takes); p99 STOPPED-to-ready ≤ 3 s.
  planB: Gate post-processing on the OBS log line in ~/Library/Application Support/obs-studio/logs/<latest>.txt and/or poll until moov is the last top-level box, with a 60 s timeout and a clear error.
- [high] Event-to-video error exceeds ±100 ms because STARTED receipt is used as T0 and iPhone-to-OBS capture latency is ignored.
  why: STARTED goes through the Qt UI thread, has no timestamp, and is emitted before the first frame. outputDuration is frame-quantized and lags by the encoder pipeline. iPhone USB mirroring latency into OBS is unknown and may be tens to hundreds of ms.
  spike: In a pre-roll: (a) 8 SerialFrame flash markers at random 400–900 ms gaps, logging Mac hrtime at send; (b) 5 device-side visible events at known device-monotonic times (e.g. runner-host full-screen flash), mapped to Mac time with the transport clock sync; (c) GetOutputStatus('simple_file_output') polled at 4 Hz throughout. Detect flash frames with ffmpeg signalstats and compute residuals.
  success: Mac-to-recording residual stdev ≤ 5 ms, max ≤ 17 ms; capture latency L_cap measured with stdev ≤ 17 ms and stable across 3 sessions; end-to-end device event to video frame within ±50 ms (half the ±100 ms budget).
  planB: Calibrate L_cap per take from a device-side pre-roll event, and use the GetOutputStatus regression (T0 = min over samples of t_send − N·Δ) plus a constant encoder lag measured once.
- [medium] Audio clap on track 2 has unpredictable request-to-play latency or leaks into the final mix.
  why: Playback start is stamped after media open/seek in the media thread; OBS audio buffering may grow on first use. All sources default to all 6 tracks (mixers=0xFF), and Simple mode with RecQuality='Stream' records only track 1.
  spike: Create an ffmpeg_source with a 20 ms 1 kHz WAV, restart_on_activate=false, close_when_inactive=false; tracks {'1':false,'2':true}; monitor NONE. Remove '2' from all other inputs; set RecQuality='Small' and RecTracks='3'. Pre-warm once before recording, then trigger 20 RESTARTs at random times. Measure onset per clap in 0:a:1 (silencedetect or astats) against Mac send hrtime, and RMS of 0:a:0 around each clap.
  success: Onset residual stdev ≤ 5 ms and max ≤ 15 ms after linear fit; track 1 shows no clap energy (below −80 dBFS at clap times); the recording has exactly 2 audio streams.
  planB: Use only the SerialFrame visual markers in a trimmed pre-roll, or a cropped canvas-margin strip.
- [medium] Encoder or render lag skips frames, so the file timeline drifts from wall clock and breaks the linear time mapping.
  why: Encoder pts counts encoded frames; skipped frames compress the file timeline against wall time (and against audio).
  spike: Record 10 min at 1170x2532@60 with apple_h264 (Simple mode, Small/HQ) on the M4 while the iPhone capture runs. Diff GetStats renderSkippedFrames/outputSkippedFrames and GetOutputStatus outputSkippedFrames between start and stop; compare outputTotalFrames×Δ with wall-clock duration.
  success: 0 skipped or lagged frames; |frames×Δ − wall duration| ≤ 1 frame over 10 min.
  planB: Drop to 30 fps or a lower output resolution (e.g. 886x1920 even dimensions), use hardware HEVC, and abort the take if the skipped-frame delta is above 0.
- [medium] Unattended OBS blocked by modals: Safe Mode prompt after a crash (websocket disabled), profile-switch restart question, or StartRecord failure dialogs.
  why: Safe Mode excludes obs-websocket; ActivateProfile may ask to restart when audio settings differ; StartRecord/StopRecord are fire-and-forget, so failures show only as OBS dialogs.
  spike: Kill OBS (SIGKILL) and relaunch with and without --disable-shutdown-check; switch between Untitled and Contrarregra profiles via SetCurrentProfile; fill a small test volume to trigger the low-disk path.
  success: With the recommended launch flags and matching [Audio] settings, no modal appears in 5/5 runs; the tool detects a failed start within 5 s (no STARTED event) and reports it.
  planB: Launch OBS with --profile/--collection instead of switching at runtime; enforce a Mac-side disk-space guard before StartRecord; alert the human on any start timeout.
- [blocker] obs-websocket server disabled or unreachable at take time.
  why: config.json has server_enabled=false today; there is no CLI flag to enable it, and the tool must not edit config.json because it contains the password.
  spike: Owner enables it once via Tools > WebSocket Server Settings. Tool doctor: connect to ws://127.0.0.1:4455 with subprotocol obswebsocket.json, read Hello (no password needed), then Identify with the Keychain password.
  success: Doctor reports obsStudioVersion=31.1.2, obsWebSocketVersion=5.6.2, rpcVersion=1, auth required, Identified in under 200 ms.
  planB: Manual QuickTime recording (the owner's stated plan B) with chapters generated in post from the event log.
- [low] Out-of-order execution of separate requests (thread pool) produces wrong sequencing, e.g. a chapter before the recording is active or settings applied after start.
  why: Each message is dispatched to QThreadPool; only batches are serial.
  spike: Fire StartRecord and CreateRecordChapter back-to-back without awaiting, 50 times, and count 501 errors; repeat with await-then-send.
  success: The awaited pattern gives 0 ordering errors in 50 runs.
  planB: The client library enforces one in-flight request per logical sequence; ordered multi-step operations go through RequestBatch with haltOnFailure=true.
- [medium] obs-websocket-js call() hangs forever after an OBS restart or disconnect, freezing the MCP server or CLI.
  why: Pending promises are never rejected (listeners are removed on close); there are no timeouts and no reconnect.
  spike: With obs-websocket-js/json, issue a Sleep batch of 5 s and quit OBS mid-batch; observe the promise state after 30 s.
  success: The chosen client rejects all in-flight requests within 1 s of close and reconnects with backoff (except after 4009/4011).
  planB: Use the in-house zero-dependency client, or wrap obs-websocket-js with per-call Promise.race timeouts and a close handler that rejects a tracked pending set.
- [medium] Wrong ffmpeg used for post (PATH resolves to 4.4.7), or remux fails or loses chapters (bin_data chapter stream with -map 0; ffmetadata chapters ignored without -map_chapters 1).
  why: ffmpeg@4 is linked over 8.1.1. The mov demuxer exposes the chapter track as a data stream (bin_data), which the MP4 muxer likely cannot write. ffmpeg auto-takes chapters from the first input that has them.
  spike: On a test OBS hybrid MP4: run 8.1.1 'ffmpeg -i in.mp4 -map 0 -c copy out.mp4' (expect a failure) and 'ffmpeg -i in.mp4 -i ch.ffmeta -map 0:v:0 -map 0:a:0 -map_metadata 1 -map_chapters 1 -c copy -movflags +faststart out.mp4'; then ffprobe -show_chapters out.mp4. Also trim with -ss 3.
  success: The explicit-map command succeeds; out.mp4 has the ffmeta chapters (QT and Nero), shifted correctly after -ss; track 2 (clap) is absent.
  planB: Pin /opt/homebrew/opt/ffmpeg/bin/{ffmpeg,ffprobe} in config, check the version in doctor, and always pass explicit -map and -map_chapters.

## RECOMMENDATIONS
- Target obs-websocket 5.6.2 / RPC 1 exactly. Vendor docs/generated/protocol.json@5.6.2 (commit 40d26db) to generate TS types. At connect, check Hello.obsStudioVersion=='31.1.2', obsWebSocketVersion=='5.6.2', rpcVersion==1, and that GetVersion.availableRequests includes CreateRecordChapter, CreateRecordChapter's dependencies, and Sleep.
- Write a small in-house client (Node 22 global WebSocket + node:crypto, JSON subprotocol, ~150–250 lines). Features: per-request timeout, reject-all on close, reconnect with backoff (never after close codes 4009/4011), hrtime stamped at send and receive for every message, and a single ordered command queue. If obs-websocket-js is used instead, import 'obs-websocket-js/json' and wrap every call in a timeout.
- Identify with eventSubscriptions=323 (General|Config|Outputs|MediaInputs). Treat RecordStateChanged as the only truth for record state. StartRecord: await the response, then await STARTED (5 s timeout, then GetRecordStatus). StopRecord: await STOPPED, then wait for file finalization (stable size + ffprobe OK, or the OBS log line 'MP4 file output complete').
- Use a dedicated OBS profile 'Contrarregra' and scene collection 'Contrarregra', created once. Profile settings: Output.Mode=Simple, RecFormat2=hybrid_mp4 (the default for new profiles in 31.1.2), RecQuality=HQ or Small (not 'Stream' if a second audio track is wanted), RecTracks='1' (or '3' with the clap), FilePath=~/Movies/contrarregra; canvas/output 1170x2532 at 60/1 via SetVideoSettings when idle; [Audio] identical to the other profile. Launch OBS with: open -a OBS --args --profile Contrarregra --collection Contrarregra --disable-shutdown-check --disable-missing-files-check.
- Do not change RecFormat2 at runtime to enable chapters. If the doctor finds RecFormat2 != 'hybrid_mp4', fail with instructions (switch profile or restart OBS), because the output object type is fixed until outputs reset.
- Never read obs-websocket config.json or pass --websocket_password. Read OBS_WEBSOCKET_PASSWORD from the Keychain into memory only, and never log the Identify payload. Health-check with the unauthenticated Hello. The server binds to all interfaces (no localhost-only option in 5.6.2), so keep auth on and a strong password.
- Before StartRecord: GetStats.availableDiskSpace (MiB, recording volume) plus a Mac-side statfs, aborting below a threshold. During the take: poll GetOutputStatus('simple_file_output') at 4 Hz, logging (t_send, t_recv, outputTotalFrames, outputSkippedFrames). Snapshot GetStats render/output skipped frames at start and stop, and mark the take invalid if the deltas are above 0.
- Chapters: call CreateRecordChapter at each scene boundary only after STARTED, and never while paused (it returns 702). Expect each chapter to land a few frames early (DTS of the last muxed frame). Make post-generated chapters authoritative: build ;FFMETADATA1 (TIMEBASE=1/1000, escaped titles) from the scene log mapped to recording time, then run /opt/homebrew/opt/ffmpeg/bin/ffmpeg -i take.mp4 -i chapters.ffmeta -map 0:v:0 -map 0:a:0 -map_metadata 1 -map_chapters 1 -c copy -movflags +faststart out.mp4.
- Time base for the ±100 ms goal: run a short pre-roll in every take, trimmed in post (confirm with owner that a head trim is allowed). It contains (1) 6–8 SerialFrame batches flashing a hidden full-canvas color source, for Mac-to-recording offset to a few ms, and (2) 3–5 device-side visible events at known device-monotonic times, for iPhone-to-OBS capture latency. Combine these with the device-to-Mac clock offset from the USB transport. Keep the 4 Hz outputTotalFrames log as a drift and skip check.
- Use the optional track-2 audio clap (ffmpeg_source, tracks {'1':false,'2':true}, monitor NONE, every other input with '2':false, RecTracks='3') only if the spike shows ≤5 ms jitter. It is the only marker that can repeat throughout the take without showing in the final video. Final mix/export maps only 0:a:0.
- Never put UI-thread-waiting requests (SetCurrentProfile, CreateProfile, SetCurrentSceneCollection) inside SerialFrame batches. Keep batches short because they cannot be cancelled. Use haltOnFailure=true for setup sequences.
- Human checkpoints: prefer keeping the recording running and marking the span, so the frame-to-time mapping stays continuous. If PauseRecord is used to hide passcode or Face ID UI, note that chapters cannot be added while paused and that the paused span is absent from the file. The outputTotalFrames log stays consistent across pauses, but wall-clock mapping needs a pause offset.
- Doctor checks: obs-websocket reachable; versions; current profile name; RecFormat2=='hybrid_mp4'; GetVideoSettings == 1170x2532 @60/1; record directory outside the repo; iPhone capture input present in GetInputList (macos-avcapture); ffmpeg/ffprobe pinned to 8.1.1 (PATH has 4.4.7).

### F3 [verified] Auth algorithm confirmed in server code: secret = base64(SHA256(utf8(password)+salt)); authentication = base64(SHA256(secret+challenge)). The Identify example in the docs is not a test vector.
GenerateSecret hashes the password bytes plus the salt string with QCryptographicHash Sha256 and base64-encodes it. CheckAuthenticationString hashes secret+challenge and base64-encodes it. The salt is generated once per server start and the challenge once per session. In Node 22: const h=s=>crypto.createHash('sha256').update(s,'utf8').digest('base64'); auth=h(h(pw+salt)+challenge). I ran this on the documented example values ('supersecretpassword' with the doc's salt/challenge) and got '1Ct943GAT+6YQUUX47Ia/ncufilbe6+oD6lY+5kaCu4=', not the doc's 'Dj6cLS+...'. That example is illustrative only, so unit tests must use self-computed vectors. When auth is required and the string is missing or wrong, the server closes with 4009.

### F5 [verified] Every incoming WebSocket message runs on a QThreadPool, so separate requests (and events) from one client can execute and be answered out of order. Only a RequestBatch is serial.
WebSocketServer::onMessage calls _threadPool.start(...) per message, and BroadcastEvent also runs on the pool. Two Requests sent back-to-back without awaiting can run concurrently (e.g. CreateRecordChapter can overtake StartRecord). The STARTED event can arrive before or after the StartRecord response. Client rule: await every response before sending a dependent request, or put ordered steps in a RequestBatch. Batches also block one pool thread until done and cannot be cancelled.

### F8 [verified] Chapter time is the DTS of the last video packet (track 0) the muxer received at call time, in ms. It lands early relative to 'now'. An automatic chapter at 0 named 'Start'/'Iniciar' is added if the first user chapter is after 0. Chapters are written only at finalization.
mp4_output_packet sets last_dts_usec = packet->dts_usec - start_time for every video track-0 packet. mp4_add_chapter_proc stores chap->dts_usec = last_dts_usec. The chapter therefore sits at the content time of the newest encoded frame, which trails real time by the encoder plus interleave latency (and DTS can trail PTS by B-frame reorder). mp4_mux_add_chapter inserts MP4Output.StartChapter at 0 ('Start' en-US, 'Iniciar' pt-BR) when the first chapter has dts>0. Chapters are buffered and muxed in mp4_output_actual_stop, so a crash loses all chapters (the recoverable fragmented file has none). Titles are stored as 16-bit length plus raw UTF-8, max 65535 bytes.

### F9 [likely] Hybrid MP4 chapter storage: an Apple/QuickTime chapter text track (codec 'text', timescale 1000) referenced by tref/chap from every A/V track. OBS writes no Nero 'chpl'. The internal 'Dummy' end marker never becomes a sample.
add_chapter_track creates TRACK_CHAPTERS, CODEC_TEXT, timescale 1000. mp4_write_trak writes tref->chap(track_id) for non-chapter tracks. grep finds no 'chpl' in mp4-mux.c. At final flush a 'Dummy' packet is pushed at the longest track duration. process_packets only emits samples up to the penultimate packet, so Dummy only sets the last real chapter's duration. Soft-remux at finalize writes the full moov at the end and rewrites the header so that ftyp + one big mdat wrap the fragments, giving a regular MP4 to parsers.

### F10 [verified] ffprobe/ffmpeg read OBS chapters from the QT chapter track. ffmpeg auto-copies chapters on remux with -ss/-t offsets applied, and the MP4 muxer writes both QT chapter track and Nero chpl.
libavformat/mov.c mov_read_chapters: for each tref/chap track it turns the stream into AVMEDIA_TYPE_DATA / AV_CODEC_ID_BIN_DATA with discard=ALL, and makes an AVChapter per sample (title = 16-bit length + UTF-8, or UTF-16 with BOM). Use: ffprobe -v error -of json -show_chapters take.mp4. fftools/ffmpeg_mux_init.c copy_chapters: with no -map_chapters, chapters come from the FIRST input that has any, shifted by -ss (ts_offset) and clipped by -t. -map_chapters N selects the input, -1 disables. movenc writes a QT chapter track (MODE_MP4/MOV/IPOD with chapters, not fragmented) plus a Nero chpl unless -movflags disable_chpl. FFMETADATA header is ';FFMETADATA1' with [CHAPTER] TIMEBASE=1/1000 START= END= title= ('=', ';', '#', '\' and newline escaped with backslash); the docs summary on ffmpeg.org fetched as 'ffmetadata version=1', which is wrong per source.
